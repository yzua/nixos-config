# Selecting software for a small NixOS + Home Manager flake

**Researched 2026-09-26.** Primary references: NixOS manual **26.05**, Nixpkgs manual **26.05**, Nix reference manual **2.34.9**, nix.dev, and the online Home Manager manual/options. The Home Manager option site is not a snapshot of this repository's pin: confirm an option in the pinned release before using it. This is a decision guide with a **selective** old-to-new inventory, not a verified inventory of package versions, licenses, or cache hits. No installations or builds were performed.

## Default decision: smallest appropriate scope

| Need | Put it here | Decision rule and source |
| --- | --- | --- |
| Login, network, hardware integration, firewall, machine-wide daemon or app intentionally for every user | NixOS service/program option; `environment.systemPackages` only for a plain system-wide package | A package in the system profile is not always sufficient: D-Bus or systemd registration may need a NixOS module. [NixOS package management](https://nixos.org/manual/nixos/stable/#sec-declarative-package-mgmt), [NixOS GNOME setup](https://nixos.org/manual/nixos/stable/#sec-gnome-enable) |
| Personal browser, password manager, desktop app, shell/CLI preferences, or user session service needed regularly | Standalone Home Manager `programs.*`, `services.*`, or `home.packages` | Home Manager manages the user's programs **and** home configuration; `home.packages` adds packages to that user's environment. [HM introduction](https://nix-community.github.io/home-manager/introduction.html), [`home.packages`](https://nix-community.github.io/home-manager/options/home-manager/home.html#opt-home.packages), [HM standalone installation](https://nix-community.github.io/home-manager/installation/standalone.html) |
| Compiler, runtime, SDK, formatter, linter, test utility or other version-sensitive tool for a particular codebase | That project's `devShells.<system>.<name>` / `mkShell` (or `shell.nix`) | The shell's packages and environment travel with the project instead of expanding the permanent home/system profile. [`nix develop` output selection](https://nix.dev/manual/nix/stable/command-ref/new-cli/nix3-develop.html#flake-output-attributes), [declarative shell tutorial](https://nix.dev/tutorials/first-steps/declarative-shell.html), [`mkShell` reference](https://nixos.org/manual/nixpkgs/stable/#sec-pkgs-mkShell) |
| One-off inspection or experiment | `nix shell <flake-ref>#<attribute>` without declaring it globally | Provides programs on `PATH` for the shell/command; it is not a persistent profile choice. [Nix shell reference](https://nix.dev/manual/nix/stable/command-ref/new-cli/nix3-env-shell.html#description), [ad hoc shell tutorial](https://nix.dev/tutorials/first-steps/ad-hoc-shell-environments.html) |

**Selection heuristic:** for each old entry, record *the current task it enables*, *how often it is used*, *whether an existing module or GNOME already provides it*, and *whether it needs privileges/a running service*. Keep only current, named needs; defer historical, duplicate, and speculative tools. This is a minimalism recommendation derived from the four scopes above, not a Nix requirement. In particular, a project tool may intentionally also exist in the user's regular `PATH`, but that overlap should have a reason. [NixOS package management](https://nixos.org/manual/nixos/stable/#sec-package-management), [HM `home.packages`](https://nix-community.github.io/home-manager/options/home-manager/home.html#opt-home.packages), [ad hoc shells](https://nix.dev/tutorials/first-steps/ad-hoc-shell-environments.html).

## Module before bare package, when behavior matters

- Check NixOS/HM **option definitions** before moving a package name across layers. NixOS explicitly warns that `environment.systemPackages` alone may omit global D-Bus/systemd setup. HM `programs.git.enable` selects a Git package and writes Git configuration; `programs.firefox` can manage package, profiles and preferences. Use a bare `home.packages` entry when no configuration/integration is wanted; do not declare both a module's installed package and an identical bare package without a reason. [NixOS manual](https://nixos.org/manual/nixos/stable/#sec-declarative-package-mgmt), [HM Git options](https://nix-community.github.io/home-manager/options/home-manager/programs/git.html#opt-programs.git.enable), [HM Firefox options](https://nix-community.github.io/home-manager/options/home-manager/programs/firefox.html#opt-programs.firefox.enable), [`home.packages`](https://nix-community.github.io/home-manager/options/home-manager/home.html#opt-home.packages).
- A module is **not** a license to enable every integration. HM's KeePassXC option manages browser native messaging and warns about a conflict with KeePassXC's own manifest updater; choose settings only for functionality actually used. Keep private databases/credentials out of declarative text. [HM KeePassXC options](https://nix-community.github.io/home-manager/options/home-manager/programs/keepassxc.html#opt-programs.keepassxc.enable), [NixOS manual on world-readable Nix paths](https://nixos.org/manual/nixos/stable/#module-services-keycloak).

## Nix tooling and package admission checks

- Treat the **system's Nix daemon/settings** as host policy, not as another user-app bundle. Home Manager can manage user-level Nix settings and registries, but its `nix.package` defaults to `null`; don't add an extra Nix executable merely to get project tools. If ad hoc commands must use the same Nixpkgs revision as a flake, make their flake reference explicit: `nixpkgs` alone is a registry lookup, not automatically the current project's pin. [Nix `nix.conf` settings](https://nix.dev/manual/nix/stable/command-ref/conf-file.html#configuration-file), [HM Nix options](https://nix-community.github.io/home-manager/options/home-manager/nix.html#opt-nix.package), [flake references/locks](https://nix.dev/manual/nix/stable/command-ref/new-cli/nix3-flake.html#flake-references).
- Add optional convenience tooling only for a demonstrated workflow: e.g. `programs.direnv` for automatic project-shell entry, `programs.nix-index` for file lookup, or `programs.gh` if GitHub CLI is used. They are separate HM options, not prerequisites for NixOS or a dev shell. [HM direnv](https://nix-community.github.io/home-manager/options/home-manager/programs/direnv.html#opt-programs.direnv.enable), [nix.dev automatic environments](https://nix.dev/guides/recipes/direnv.html), [HM nix-index](https://nix-community.github.io/home-manager/options/home-manager/programs/nix-index.html#opt-programs.nix-index.enable), [HM gh](https://nix-community.github.io/home-manager/options/home-manager/programs/gh.html#opt-programs.gh.enable).
- For **each candidate and the exact pinned package set**, search for its attribute, inspect the package definition/metadata (`meta.license`, `meta.platforms`, `meta.broken`, `meta.knownVulnerabilities`) and check whether a module already supplies it. Nixpkgs blocks unfree, unsupported, broken or known-insecure packages at evaluation by default; avoid blanket `allowUnfree` or `allowInsecure` when only an explicitly reviewed exception is needed. A successful search is **not** a cache-availability test. [Nix search reference](https://nix.dev/manual/nix/stable/command-ref/new-cli/nix3-search.html), [Nixpkgs package-policy reference](https://nixos.org/manual/nixpkgs/stable/#chap-packageconfig), [Nixpkgs unfree predicates](https://nixos.org/manual/nixpkgs/stable/#sec-allow-unfree).
- Before accepting a large dependency, preview its exact output/closure: `nix build --dry-run --no-write-lock-file '<pinned-flake-ref>#<attribute>'` reports planned fetches/builds without executing them. Once an **exact output store path** is known, `nix path-info --recursive --store https://cache.nixos.org/ /nix/store/<exact-output>` can query that cache and its closure without building or substituting; repeat for other **already configured and trusted** caches. Check the full closure, not just the top-level output, before concluding it is cheap to use. Nixpkgs warns unfree packages are not built by its CI/cache; other packages/overrides may also be missing. Do not silently accept a major local compilation; investigate a maintained prebuilt Nixpkgs variant or an official binary packaged and verified through Nix if suitable, then ask before any significant build. [`nix build --dry-run`](https://nix.dev/manual/nix/stable/command-ref/new-cli/nix3-build.html#opt-dry-run), [`nix path-info` and cache query](https://nix.dev/manual/nix/stable/command-ref/new-cli/nix3-path-info.html#examples), [Nixpkgs cache and unfree caveat](https://nixos.org/manual/nixpkgs/stable/#chap-packageconfig), [NixOS prebuilt-executable caveat](https://nixos.org/manual/nixos/stable/#sec-declarative-package-mgmt).
- A cache is a **trust decision**, not a fix for an inconvenient source build. `substituters` and `trusted-public-keys` govern downloads; Nix requires trusted signatures for non-content-addressed paths by default. Adding a signing key authorizes its holder to substitute executable store objects. Do not add unknown caches, disable signature checks, or grant `trusted-users` casually (the Nix manual equates that to root access). [Nix substitution/signature/trusted-user settings](https://nix.dev/manual/nix/stable/command-ref/conf-file.html#conf-substituters), [nix.dev cache trust warning](https://nix.dev/guides/recipes/add-binary-cache.html).

## Desktop and optional stacks: opt in, don't recreate the old bundle

- **GNOME:** enable the GNOME desktop and recommended GDM with NixOS options; inspect its included core apps/services before adding alternatives. Use `environment.gnome.excludePackages` for selected bundled apps, or `services.gnome.core-apps.enable = false` if deliberately removing all core apps; the manual warns disabling GNOME core services can break applications. Put per-user GSettings/dconf values in HM rather than duplicating system vendor defaults: overrides change **defaults**, not an already-set user value. Avoid a second display manager, keyring, portal, SSH agent, or session service unless a real requirement and ownership decision justify it. [GNOME manual](https://nixos.org/manual/nixos/stable/#chap-gnome), [GNOME service warning](https://nixos.org/manual/nixos/stable/#sec-gnome-enable), [GSettings versus user values](https://nixos.org/manual/nixos/stable/#sec-gnome-gsettings-overrides), [HM dconf](https://nix-community.github.io/home-manager/options/home-manager/dconf.html#opt-dconf.settings), [HM keyring/SSH agent](https://nix-community.github.io/home-manager/options/home-manager/services/gnome-keyring.html#opt-services.gnome-keyring.enable).
- **Security:** a client (`programs.ssh` HM) is different from an incoming SSH *server* (NixOS service); enable the latter, its authentication and firewall policy only for a remote-access use case. Select one intended SSH-agent provider if choosing between GNOME Keyring, `services.ssh-agent` and `services.gpg-agent.enableSshSupport`. Never put tokens, passwords, private keys or decrypted vault contents into `home.file.text`, Nix settings, service environment literals, or Git: Nix paths/config can become world-readable store objects. [HM SSH client](https://nix-community.github.io/home-manager/options/home-manager/programs/ssh.html#opt-programs.ssh.enable), [NixOS SSH example](https://nixos.org/manual/nixos/stable/#sec-user-management), [HM agents](https://nix-community.github.io/home-manager/options/home-manager/services/gpg-agent.html#opt-services.gpg-agent.enableSshSupport), [HM OpenCode secret-file option](https://nix-community.github.io/home-manager/options/home-manager/programs/opencode.html#opt-programs.opencode.web.environmentFile).
- **AI:** keep only the agent CLI(s) used regularly as personal tools; prefer a project's dev shell for a project-specific CLI/version. A local inference server is a distinct, opt-in service with a network listener, not a requirement for a hosted-model CLI. Check the pinned HM release for any `programs.opencode`/`services.ollama` options, and review network binding, hardware dependencies, license and cache/build costs before enabling either. Keep API keys outside Nix values. [HM OpenCode options](https://nix-community.github.io/home-manager/options/home-manager/programs/opencode.html#opt-programs.opencode.enable), [HM Ollama server/listen option](https://nix-community.github.io/home-manager/options/home-manager/services/ollama.html#opt-services.ollama.host), [Nixpkgs cache/license caveat](https://nixos.org/manual/nixpkgs/stable/#chap-packageconfig).
- **Development:** default to per-repository `devShells` for language toolchains and formatters; add a persistent editor, VCS or shell integration to HM only if useful across projects. Container engines/user services and databases are separate operational choices: first identify whether the project needs a temporary build tool, a per-user service, or a host service, then configure that owner rather than copying a full workstation stack. [`nix develop`](https://nix.dev/manual/nix/stable/command-ref/new-cli/nix3-develop.html), [project shell tutorial](https://nix.dev/tutorials/first-steps/declarative-shell.html), [HM user Podman services](https://nix-community.github.io/home-manager/options/home-manager/services/podman.html#opt-services.podman.enable), [NixOS module warning](https://nixos.org/manual/nixos/stable/#sec-declarative-package-mgmt).

## Applied to this configuration

The old recovery bundle's `System/home-manager/packages/{cli,applications,development,networking,privacy,system-monitoring}.nix`, `System/home-manager/modules/{terminal,apps}/`, and `System/nixos-modules/default.nix` describe a much broader workstation than the present GNOME flake. This is a prioritized shortlist, **not** an instruction to transplant its package hub or enable all its services:

| Decision | Old tools / current status | Recommendation |
| --- | --- | --- |
| Keep, do not duplicate | The new `hosts/PC/default.nix`, `modules/nixos/{base,development,gnome}.nix`, and `home-manager/home.nix` already declare GNOME, Git, Just, Node.js, pnpm, Firefox, KeePassXC, Telegram and `gh`. `home-manager/modules/ai.nix` declares a large AI selection. | Do not add a second package entry for something already managed by its module or another layer. These are *declared*, not proof of activation. If minimizing further, review which AI agents are actually used before changing their package list; leave their mutable login data alone. |
| Small first addition to the **user** profile | Old `packages/cli.nix` had `ripgrep`, `fd` and `jq`; the terminal modules enabled `fzf`, among many alternatives. | Consider `ripgrep`, `fd`, `jq`, `fzf` for frequent cross-project search, navigation and data work. Add `bat` and `btop` only if you want their terminal interfaces. Shell key bindings for `fzf` or `zoxide` need an explicit shell integration choice; the new Home Manager profile does not manage a shell. Check pinned packages/cache availability before any actual addition. |
| Add only if regularly used | The old terminal/app modules enabled Ghostty, Yazi, Zellij, mpv, Zathura, Neovim, VS Code, OBS and multiple browsers. | Pick your preferred terminal/editor and any actual media apps one by one. GNOME and Firefox are already selected; do not restore the Niri/Noctalia session, browser collection, or competing desktop integration merely because the old modules imported them. A customized OBS override may lose binary-cache reuse. |
| Project shell or one-off | Old `packages/development.nix` and `packages/lsp-servers.nix` placed many compilers, servers, DB clients and reverse-engineering tools in every user session. Old JS activation installed a second set of global Bun tools at activation time. | Put language runtimes, LSPs and test tools into each relevant project's dev shell; use a temporary shell for infrequent network/security/Android tools. The new flake's own dev shell already has `nixfmt`, `shfmt`, `statix`, `deadnix`, ShellCheck, `sops` and `age`. Avoid network-driven global installs in Home Manager activation. |
| Separate, deliberate **service** decisions | The old host defaults enabled Docker, libvirt, Waydroid, Tor, VPN, DNS proxy, security scanners, dashboards and more. The old Restic backup module existed, but `host-defaults.nix` left `backup.enable` **false** and no host override was found. | Do not turn these on as a package bundle. Prioritize choosing a real backup destination, secret handling and a test restore; enable one backup solution only when that design is ready. Syncthing, if needed, is file sync rather than a backup. Enable Steam/firmware updates/virtualization/network services only for an actual hardware or workflow requirement. |

The recovery bundle contains credential material. Do not copy its plaintext keys or tokens into this flake or the Nix store. This section is based on the local old/new source files and the scope rules cited above; it does **not** assert that any proposed new package is cached, safe to build, or installed.

**Practical outcome:** make a short *keep now / project only / try temporarily / defer* list from actual workflows, then check pinned options, metadata and binary substitution **per proposed change**. No package in this note is an unconditional recommendation or a claim that its current build is cached. [NixOS package management](https://nixos.org/manual/nixos/stable/#sec-package-management), [HM introduction](https://nix-community.github.io/home-manager/introduction.html), [Nix path-info](https://nix.dev/manual/nix/stable/command-ref/new-cli/nix3-path-info.html).
